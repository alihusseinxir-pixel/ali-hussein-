# Environment variables

Every variable the application reads (found by scanning `src/` and `scripts/`). Real values live **only** in Render's dashboard
(or a local, git-ignored `.env`). `.env.example` lists the names with empty values; `render.yaml` marks the secret ones `sync: false`.

Legend — **Where**: `web` = the web service, `cron` = the reminders cron job. **Secret**: ● never commit, never paste in chat.

## Set automatically by `render.yaml` (do not type these)

| Variable | Where | Value | Notes |
|---|---|---|---|
| `DATABASE_URL` ● | web, cron | from the `basma-db` database (`connectionString`) | Render's *internal* URL. Used by Prisma. |
| `SESSION_SECRET` ● | web | generated by Render | Signs session cookies, share links and upload tokens. Rotating it signs everyone out and invalidates outstanding share links. 32+ characters required. |
| `NODE_VERSION` | web, cron | `22` | Tells Render which Node to use. |
| `APP_TIMEZONE` | web, cron | `Asia/Baghdad` | One timezone for the whole organization (dates, calendar, reminders). Change if needed (any IANA name). |
| `ALLOW_SIGNUP` | web | `true` | **Set to `false` after you have created your organization.** While `true`, anyone with the URL can create a new organization. |
| `WEEK_START` | web | `0` | First day of the calendar week: 0 Sunday, 1 Monday, 6 Saturday. |
| `PRESIGN_TTL_SECONDS` | web | `300` | Lifetime of upload/download links (30–900). |
| `MAX_UPLOAD_MB` | web | `100` | Largest file accepted. |
| `DEADLINE_REMINDER_HOURS` | cron | `24` | "Deadline approaching" window. |
| `PUBLISH_REMINDER_HOURS` | cron | `2` | "Time to publish" window. |

## You must enter these in Render (Blueprint prompts for them)

| Variable | Where | Secret | What to enter |
|---|---|---|---|
| `APP_URL` | web **and** cron | no | The exact public address, e.g. `https://basma-marketing.onrender.com` or your own domain. No trailing slash. Used in email links and as the S3 CORS origin. |
| `S3_BUCKET` | web | no | Your production bucket name. Setting it switches file storage to S3. |
| `AWS_REGION` | web | no | The bucket's region code, exactly (e.g. `eu-central-1`). Not the city name. |
| `AWS_ACCESS_KEY_ID` ● | web | **yes** | Access key of the *production* IAM user (object permissions only). Render is not AWS, so a role cannot be used here. |
| `AWS_SECRET_ACCESS_KEY` ● | web | **yes** | Its secret. Set both keys or neither (the app refuses half a pair). |

## Optional / only in special cases

| Variable | When |
|---|---|
| `SMTP_URL` ● , `MAIL_FROM` | Turn on automatic email (invitations, password reset, notification digests): add them on the web service **and** the cron job. Without `SMTP_URL` the Team page shows invitation and reset links for you to send yourself, and notifications stay in the app. e.g. `smtps://USER:PASSWORD@smtp.provider.com:465`; the sender must be verified at your provider. |
| `S3_ENDPOINT`, `S3_FORCE_PATH_STYLE`, `S3_PREFIX` | Cloudflare R2 / MinIO / another S3-compatible provider, or a folder inside the bucket. Not needed for AWS S3. |
| `STORAGE_DRIVER` | Force `local` or `s3`. Normally derived from `S3_BUCKET`. Leave empty. |
| `STORAGE_DIR` | Local-disk folder when the local driver is used (development only). |
| `CRON_SECRET` ● | Only if you trigger reminders over HTTP (`POST /api/cron/reminders`) instead of the Render cron job. Empty = that endpoint is disabled. |
| `AWS_S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Older alias names, still accepted. Do not use them in new setups. |

## Provided by the platform

| Variable | Notes |
|---|---|
| `PORT` | Render sets it; `next start` listens on it. |
| `NODE_ENV` | `next start` runs in production mode (secure cookies, no email printing). |

## Checks you can run

- Names present in code ⊆ this document: see the scan command in `docs/DEPLOYMENT-CHECKLIST.md`.
- Hygiene tests (`src/lib/env-example.test.ts`) fail the build if `.env.example` contains a value for any sensitive name, if a real `.env*` file is tracked, or if a source file contains an AWS key.
- Log redaction (`src/lib/log-safe.ts`) scrubs the values of secret-named variables and credential-shaped strings from error logs.

## Local development only (not for Render)

`cp .env.example .env`, then fill `DATABASE_URL`, `SESSION_SECRET` (`node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`) and `APP_URL=http://localhost:3000`. Leave the S3 and SMTP lines empty: files go to `./uploads` and emails are printed in the terminal.
